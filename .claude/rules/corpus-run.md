# Corpus run — the pilot instrument and how far diagnostics reach

Run under the accelerator recipe, never the gate prefix (→ `gates.md`).

- **`scripts/pilot_corpus_run.py` is the standing instrument for any claim about the real corpus** — the only path that measures the run against the published tree, which no test case can reach. `--reuse-run` re-analyses an existing `--out` tree without decoding. Outputs are patient-adjacent ⇒ `.scratch/pilot-m2u81/` (gitignored), report at `pilot_report.json`.
- **It samples EVENTS, not assets** — `process_session` runs every camera of a session, so an asset cannot be drawn alone. Axis coverage first (hash-ranked event per uncovered value of `codec`, `device_config`, `rotation_deg`), then hash-ranked replication to `--min-assets`; the rule is length-free, so the sample carries no duration bias. `_select_events` raises rather than running an uncovered sample. `pts_monotonic` is reported, never required — it is confounded with codec and device on this corpus (hevc/one tablet = 0 on all 123, h264/another = 1 on all 256), so demanding it as an axis over-constrains the draw.
- **`scripts/corpus_run_2d.py` = the full-corpus driver; the pilot stays its reader.** It loads the pilot by `importlib` for the three-table join and the redaction allowlist, so the corpus claim and the pilot claim share one instrument. **Resume is keyed on `event_complete.json`** (written after an event's outputs are final) **plus a `pose_config.json` matching the invocation** — **never on output presence**, because a killed run leaves a partial CSV no row count can distinguish from a complete one. A re-attempt `rmtree`s the event tree first: partial work is destroyed, never credited. `--analyse-only` republishes manifest + report with no decode; `--limit N` runs the first N due events; exit 1 ⟺ any verdict false, which includes an unfinished run.
- **`run_manifest.csv` is total by construction**: one row per canonical registry asset, six frozen codes (`pose_estimation.corpus_run.ASSET_DISPOSITIONS`) — `ok`, `not_placed`, `not_run`, `run_failed`, `clinical_failed`, `no_landmarks`. `not_run` was **forced by the partition, not chosen**: a partial pass must still publish a total manifest, and folding "never attempted" into `run_failed` hides real failures behind resumability. `validate_manifest` enforces row count, key-set equality and key **uniqueness** as three separate conjuncts, refusing emptiness first. Count + set equality already imply uniqueness; the uniqueness check runs before the set check so a duplicate-and-drop manifest is refused as a repeat, naming its defect.
- **The event is the isolation grain, and it always publishes.** R is invoked once per event directory and its `stop()` ends that process, so one rejected asset voids that event's whole clinical pass: `_attempt_event` reads the exit code and `corpus_run.asset_disposition` lands **every** asset of that event on `clinical_failed`. The loss is recorded rather than silent, and the neighbouring event is untouched.
- **Redaction in any corpus-touching report = membership in BOTH placements, never a shape test** (M2.8.2 A09). Value admissible ⟺ published label (stratum label | R reason code | disposition code) ∪ code-authored constant the emitting program spells at its own call site. Key admissible ⟺ frozen report field name ∪ published label. A key pattern like `[a-z][a-z0-9_]*` is a **denylist wearing an allowlist's name**: it admits every identifier of that shape, so one capture id is refused as a value and admitted as a key — same string, two verdicts. It also refuses shapes the reports really publish (`_coverage` keys by integer stratum value) and has no class for the generator, its version or the device echoes. **The shape backstop is gone**: `_assert_redacted(payload, allowed, fields)` raises from `pilot_corpus_run.redaction_violations`, whose key clause is membership in `fields | allowed`, and each script declares a frozen `REPORT_FIELDS` — spelled at the call site, never harvested from the payload, because a set derived from what was emitted admits whatever leaks into it. **The suite's oracle calls that same function**; a local re-implementation cannot witness the shipped guard. A new report field is a `REPORT_FIELDS` edit, and omitting it aborts the run. **Subprocess stdout carries identifiers** (`Session 's02-…'`, camera names, paths) ⇒ redirect to log files under `--out/logs/`, never echo.
- **The published report is a function of STATE, never of the invocation.** Resume makes a report carrying `events_attempted` / `attempts_*` / `invocation_wall_s` differ between a one-pass and a two-pass run over the identical output tree, so the `run` block reads `events_complete` / `events_failed` / `events_unattempted` off the markers and the invocation's own counters print to stdout. Same rule as the wall clock one bullet up; check every published field for it, not just every published rate.
- **Both scripts refuse any writable sink overlapping the published session tree**, through the one public `multicam.published_overlap(target, tree)` that `_resolve_session_output` also uses. Checked before the first mkdir *and* again immediately before the report write: the log directory is created before validation and the report lands after both digest snapshots, so a rule applied once in the middle leaves a window at each end. Never re-copy the containment test — a fifth copy is a rule that drifts.
- **An artifact's ownership is the row's own source key, not the file's name.** `_artifacts` requires `diag["video"] == f"{event_id}/{camera_name}"` (measured 379/379 on the shipped corpus); a count-only check credits a foreign diagnostics row's frames and fallback counters to this asset. **The pilot `rmtree`s an event's output before relaunching it** for the same reason the driver does — it reads whatever is on disk afterwards, so a source producing nothing this time reads as one that produced last time's output.
- **`process_source` re-raises `KeyboardInterrupt`**; `finally` still releases the capture and writes decoded-prefix diagnostics. Returning a short latency list would let a batch driver analyse a partial CSV and mark the event complete. A return-to-raise change requires caller + test review before the gate: an uncaught interrupt halts pytest.
- **`NaN` fails every comparison, so write a tolerance check as `not abs(d) <= tol`.** An `abs(d) > tol` refusal misses a nonfinite stored CFR rate and can publish `stored_rate_equals_its_derivation` true.
- **`output/corpus-2d/` = the CORRECTED corpus** — `--tracking body`, isotropic coordinates, 193/193 events, 379/379 `ok`, `run_report.json` publishing `coord_normalization = image-isotropic-maxdim`. The defaults select the repaired generation (`--tracker subject`, GPU detector every frame, `--tracking body`); every event records its pose configuration in `pose_config.json`, and the report refuses to name a configuration the tree does not carry. The pre-fix tree no longer exists ⇒ `scripts/check_isotropy_angle_fidelity.py` refuses any tree declaring the isotropic token, and `tests/isotropy_angle_fidelity_results.json` is its durable evidence.
- **Measured whole, adopted generation (RTMW-L 384 on GPU): 14.365 h at 6.65 fps** — 50 686.88 s run
  + 1 028.86 s clinical (refresh), 337 090 frames, pose latency median 130.2 ms (264/379 assets
  above 100 ms); `pose-device=GPU` in the event `run.log`. Size any successor against it.
- **Measured whole (M2.10 generation): 8.197 h at 11.71 fps** — M2.9's devices + hand gate + camera survey, 28 779.46 s run + 729.80 s clinical, 193 events / 379 assets / **337 090 decoded frames**, manifest 379/379 `ok`, 21 168 window rows, all 11 verdicts true, `pose-device=NPU` + `det-device=GPU` in 193/193 `run.log`s; pose latency median 51.4 ms, 10/379 assets above 100 ms. Predecessors over the same frames: M2.9 5.559 h at 17.35 fps (19 429.01 s run), rtmlib-f7 7.828 h on the NPU, 8.702 h under the CPU fallback. An RTMW-m run sizes against 8.20 h with the accelerator engaged; confirm `pose-device=NPU` in its event `run.log` before believing it.
- **The camera survey decodes every source twice** (survey pass, then pose), so size a surveyed run from a **paired** probe — the same assets with `--camera-survey` and `--no-camera-survey` — never from unpaired markers: per-asset pose latency drifts between days (below) and an unpaired ratio absorbs it. **The paired probe under-sized the corpus by 23 %**: 11 assets × <= 600 frames measured 1.14× → projected 6.3 h; the corpus measured 1.481× run wall (8.20 h). Per-frame latency summed over the diag files rose 1.129× (16 808 → 18 977 s); time outside that timer rose 2 621 → 9 803 s, an increase of ~21 ms per decoded frame (M2.10 total ~29 ms) against the probe's ~10 ms increase (67.8 s over <= 6 600 frames). The survey honours `--max-frames` (`camera_survey.py` `survey_source`), so survey-cap leakage is ruled out; whether duration or asset mix (a <= 600-frame sample of 11 assets) carries the extra cost is unmeasured — a stage-timed full-duration paired probe decides it. Size the next surveyed run at 1.48× its unsurveyed whole until a probe reproduces that ratio. Read the first events' `latency_ms_mean` before trusting any projection.
- **A per-invocation accumulator paired with a whole-corpus numerator is a false rate the moment the job is resumable.** The driver divided all-corpus `frames_decoded` by the seconds THIS process spent and published 13.88 fps / 6.903 h — a rate the pipeline never reached. Fix: sum the wall from the per-event markers (`run_s`/`clinical_s`), correct across any pass count, and label `sample: corpus` only when `events_measured == events_total`. **Check every published rate for a numerator and denominator drawn from different populations.**
- **A read-only claim over the published session tree needs THREE witnesses.** `tree_digest` excludes `generation.json` (a document cannot digest itself) and `validate_generation` compares that document's *fields* — so reindenting the marker rewrites bytes inside the tree while both stay green. `sessions.generation_digest` is the third, and the run publishes `generation_marker_unmoved` beside `generation_digest_unmoved`.
- **A healthy sample cannot exercise a failure path.** The pilot's 16 input groups partitioned 16 windowed / 0 dropped, so every drop reason went untested there; the `2d_drop` golden is what pins them. Pair every real-corpus probe with a synthetic negative — the probe proves reach, the golden proves the branch.
- **Diagnostics ship only through the session path.** `process_source` writes its source-summary CSV from `output_diag`, and the single-source and batch entry points pass none, so a run outside `process_session` produces no diagnostics at all — not an empty file, no file. Any claim of the form "every asset has a disposition" holds for the session path alone.
- **A manifest disposition of `ok` certifies that an asset decoded and produced rows — never that it decoded in the orientation or the metric its column names assume.** The manifest exists to stop an asset vanishing from a denominator and does that well; orientation and coordinate-metric validity need separate checks. Totality checks answer *which assets contributed*; they are silent on *whether the contribution means what it says*.
- **Container PTS reordering cannot reach the R layer.** `pts_monotonic = 0` on 123/379 assets, but `SourceClock.timestamp()` (`video_io.py:28-77`) guarantees strictly-increasing timestamps — a regressing or repeated `cv2.CAP_PROP_POS_MSEC` falls back to `idx/fps`, then a second guard forces `last + 1/fps`. 123 is an upper bound: qualification measured PyAV demux order, the run path reads cv2 presentation order. **The CFR fallback rate is measured and it is zero** — `index_fallback` 0 + `monotonic_forced` 0 over 8971 decoded frames on 16/16 pilot assets, 4 drawn from the `pts_monotonic = 0` population. Counters ship in `SourceTimestampClock`, so any future run re-measures it per source; treat a nonzero rate as a real finding, not noise.
- **OpenCV APPLIES the container display matrix, and every corpus asset decoded upright.** Pixel identity: the bare `cv2.VideoCapture(path)` decode equals the `CAP_PROP_ORIENTATION_AUTO = 0` decode transformed by exactly the declared rotation, with explicit `CAP_FFMPEG`, explicit `CAP_ANY` and `AUTO = 1` all matching the default. **`AUTO = 0` is the only setting yielding an unrotated frame, and no code path sets it.** Corroborated on the shipped output, where rot-180 is the discriminating class because it shares rot-0's aspect: median per-asset `elbow_y − shoulder_y` reads +0.0966 / +0.0347 / +0.0378 / +0.0302 for rot-0/180/90/270, positive (upright) in all four. Registry census over the 379 `ok` assets: 341 rot-0, 27 rot-90, 10 rot-180, 1 rot-270. **Never add a rotation on the decode path**; `open_capture` sets `AUTO = 1` explicitly so the behaviour rests on an assertion rather than on a default that moved across OpenCV 4.10/4.11/4.12, and it reads the `set` return, warns, releases and returns `None` when the request is refused (measured `True` on 382/382 real assets).
- **The clinical stage names its producer per event.** `_clinical_stage` (first pass and
  `--refresh-clinical` alike) turns the marker failed before R starts and records
  `analysis_sha256` (the R file it ran) on completion; the report's
  `configuration.analysis_sha256` is the digest every complete event records, else `mixed`
  with verdict `clinical_method_uniform` false. An edit to `analysis/clinical_features.R` leaves
  an existing tree reporting the producer its events ran (stale, not `mixed`); `mixed` = events
  that ran different producers (an interrupted refresh, a resume across an edit, pre-digest
  markers). `corpus_run_2d.py --model ARM --out DIR --analyse-only --refresh-clinical` reruns R
  over every complete event (landmarks untouched; no device needed) and brings the tree onto the
  current producer.
- **A run's `pose_config.json` records the `--model` name exactly as given** (M2.10: `rtmw-l`;
  M4 trees: `rtmw-l-384`, `rtmw-m-256`), so the alias and its target are different configs.
  `--analyse-only`, `--refresh-clinical` and `--reuse-run` refuse a complete event whose recorded
  config differs from the invocation's ("produced under another pose configuration") → always
  pass the run's own `--model` name. Defaults = `corpus_run.DEFAULT_MODEL` = `rtmw-l-384`, the
  adopted `output/corpus-2d` (193/193 recorded configurations equal the bare driver's); `run`, both
  drivers, `bench/replay.py` `CORPUS_ARGS` and `scripts/run_report.py` read it
  (`tests/test_adopted_model_defaults.py`) → adopting another run moves that one constant in the
  same unit. The runner resolves an unset `--pose-device` after its whole-body fallback, so the
  device follows the model that loads. M2.10 trees also lack `openvino_build` + `calibration`: the
  current drivers refuse them even with `--model rtmw-l`. Republish only with their own code
  (`487f790`; `.agent/spec.md` `Artifacts`).
- **Resume = rerun the same command**: an event with a complete marker under the same config is
  skipped; a markerless event is redone. A queue script's `> corpus-<arm>.log` truncates →
  move the old log aside before relaunching.
